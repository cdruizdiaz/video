REQUERIMIENTOS COMPLETOS DE SOFTWARE — suite de producción de video (repo cdruizdiaz/video)
===========================================================================================
Inventario de TODO lo que el proyecto necesita en una PC, tomado de la PC de referencia
(Intel i3-10110U, Windows 11) el 2026-10-05. Versiones = las instaladas y probadas juntas.

Rutas: todo lo pesado vive FUERA del repo, en C:/Videos/_herramientas/ (compartido entre proyectos).
Las rutas exactas que leen los scripts están en scripts/herramientas.json (igual en todas las PC).
Los datos propios de cada PC van en C:/Videos/_herramientas/equipo.json (no se versiona).

Verificación final: node scripts/verificar-suite.mjs  +  npm test  +  npm run lint


1. SISTEMA OPERATIVO Y HARDWARE
-------------------------------
- Windows 11 (x64).
- Sin GPU NVIDIA: todo corre en CPU. RIFE y Real-ESRGAN usan Vulkan (anda con Intel UHD y AMD Radeon);
  Remotion 3D usa --gl=angle (D3D11, gráfica integrada).
- Disco: ~5 GB para C:/Videos/_herramientas (modelos + Blender + venv), más node_modules del proyecto.

ffmpeg: crear el acceso fijo (junction, sin admin) para que la ruta sea igual en todas las PC:
  New-Item -ItemType Junction -Path C:\Videos\_herramientas\ffmpeg -Target <%LOCALAPPDATA%\Microsoft\WinGet\Packages\Gyan.FFmpeg_*\ffmpeg-<versión>-full_build>
  Debe tener los filtros: ebur128, loudnorm, lut3d, silencedetect, sidechaincompress, xfade, drawtext, subtitles, arnndn.
  Tras `winget upgrade --id Gyan.FFmpeg` hay que rehacer el junction.

Windows: System.Speech (viene con Windows) — lo usa verificar-suite.mjs para generar voz de prueba.

Opcional / manual:
- DaVinci Resolve (gratis, blackmagicdesign.com) — solo para crear LUTs .cube → C:/Videos/_herramientas/luts/.
- Adobe Premiere — destino de /a-premiere (no hace falta para renderizar).
- GitHub CLI (gh) — solo para PRs/issues (winget install --id GitHub.cli).

5. PYTHON: entorno C:/Videos/_herramientas/.venv (Python 3.11.9)
---------------------------------------------------------------
Crear:   py -3.11 -m venv C:\Videos\_herramientas\.venv
Instalar: copiar el bloque de abajo a un .txt y
  C:\Videos\_herramientas\.venv\Scripts\python.exe -m pip install -r <archivo> --extra-index-url https://download.pytorch.org/whl/cpu
Claves: torch/torchaudio CPU 2.0.1/2.0.2 (DeepFilterNet), numpy<2 (1.26.4), soundfile (backend de audio de torchaudio).
En Git Bash no usar `python`/`python3` sueltos: usar el python.exe del .venv o `py -3.11`.

Qué usa cada paquete principal:
  DeepFilterNet (limpiar voz) · mediapipe (caras, pose, recorte) · opencv-contrib-python (seguimiento, mascaras)
  onnxruntime (profundidad) · librosa (pulsos de la música) · piper-tts (voz sintética) · PyMuPDF (rigs desde .ai)
  pillow (hojas de contacto) · soundfile/sounddevice (audio)

9. RECURSOS QUE NO VIAJAN CON git pull
--------------------------------------
- Música y efectos de Mixkit de public/biblioteca/: listados en public/biblioteca/LICENCIAS-mixkit.json;
  rebajarlos de a UNO con `node scripts/mixkit.mjs bajar <id> [--sfx]` (los términos de Mixkit prohíben bajar en lote)
  o copiarlos desde la otra PC. Verificar con `node scripts/mixkit.mjs verificar`.
- Crudos, audios e imágenes de cada trabajo abierto (public/trabajos/<ID>/crudos|audio|img): copiarlos desde la otra PC
  o rehacerlos según la sección "Cómo rehacerlo" de src/trabajos/<ID>/TRABAJO.md.
- Archivos .ai de personajes (C:/Videos/personajes/).
- Para el render repartido (scripts/render_partes.mjs --cola), las dos PC necesitan el mismo commit y los mismos archivos en public/.
