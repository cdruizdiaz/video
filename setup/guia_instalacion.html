Suite de producción de video

Guía para instalar el proyecto en una PC nueva y empezar a editar con Claude Code

Para Serena · Repositorio github.com/cdruizdiaz/video · Windows 11 · Actualizada el 23 de octubre de 2026

Esta guía va en orden: primero los programas básicos (VS Code y Git), después el proyecto, después Claude Code, que se encarga de instalar todo el resto por vos. Al final hay consejos para trabajar con la suite en el día a día.

Qué cambió desde la versión anterior: la instalación ahora está toda en un solo archivo del proyecto, así que el mensaje para Claude (paso 6) es más corto. Se sumaron voces de Edge TTS, la herramienta para borrar a una persona del video, motion blur, motion graphics al compás de la música y un control automático de glitches antes de cada entrega. Las novedades están marcadas con NUEVO.

1Antes de empezar

  • Windows 11 de 64 bits, con conexión a internet estable (se bajan unos 6 GB de herramientas y modelos).
  • Espacio en disco: al menos 20 GB libres en C: (herramientas, proyecto y algo de material de trabajo).
  • Cuenta de GitHub: el repositorio es privado y se usa la cuenta de GitHub de Claudio, que inicia sesión con su Gmail (botón Continue with Google). Coordiná con Claudio el momento del paso 4: puede hacer falta que confirme el ingreso desde su celular.
  • Cuenta de Claude con plan Pro o Max (o una cuenta de la organización): Claude Code la usa para iniciar sesión.
  • No hace falta placa de video NVIDIA: toda la suite corre en el procesador (y en la gráfica integrada para el 3D).
  • Internet también al trabajar: las voces de Edge TTS, las tipografías de Google Fonts y la música de Mixkit se bajan en el momento.
Cómo abrir PowerShell (la terminal de Windows)
Varios pasos se hacen escribiendo comandos en PowerShell. Cualquiera de estas formas sirve:
  1. Desde el buscador: apretá la tecla Windows (o hacé clic en Inicio), escribí PowerShell y elegí Windows PowerShell (o apretá Enter).
  2. Desde el botón Inicio: clic derecho sobre el botón de Inicio (o Windows + X) → Terminal. Se abre directamente en PowerShell.
  3. Desde VS Code (una vez instalado): menú Terminal → Nueva terminal (o Ctrl + ñ). Se abre abajo, ya ubicada en la carpeta del proyecto.
Aparece una ventana con un texto tipo PS C:\Users\Serena> y el cursor titilando: ahí se escriben los comandos. Para pegar uno, copialo de esta guía, hacé clic derecho dentro de la ventana (o Ctrl+V) y apretá Enter. No hace falta abrirla “como administrador”: cuando algo necesite permisos, Windows lo pregunta.

2Instalar VS Code

VS Code es el editor donde vas a ver el proyecto y conversar con Claude.

  1. Entrá a code.visualstudio.com y descargá la versión para Windows (User Installer), o en PowerShell: 
    winget install -e --id Microsoft.VisualStudioCode
  2. En el instalador dejá tildadas las opciones “Agregar a PATH” y “Agregar la acción Abrir con Code” al menú contextual.
  3. Opcional: para tenerlo en castellano, abrí VS Code, pestaña Extensiones (Ctrl+Shift+X), buscá Spanish Language Pack e instalalo.

3Instalar Git

Git sirve para bajar el proyecto y mantenerlo sincronizado con lo que hace Claudio desde la otra PC. También lo necesita Claude Code en Windows.

  1. Descargalo de git-scm.com o en PowerShell: 
    winget install --id Git.Git -e
    En el instalador podés aceptar todas las opciones que vienen por defecto.
  2. Cerrá y volvé a abrir PowerShell (para que reconozca el comando git) y cargá tu nombre y mail; quedan registrados en cada cambio que subas: 
    git config --global user.name "Serena ..."
git config --global user.email "tu-mail@ejemplo.com"

4Crear la carpeta y clonar el proyecto

Toda la suite vive en C:\Videos. Las herramientas pesadas se instalan en C:\Videos\_herramientas y los scripts las buscan ahí, así que usá exactamente esta carpeta.

mkdir C:\Videos
cd C:\Videos
git clone https://github.com/cdruizdiaz/video.git
Iniciar sesión en GitHub con la cuenta de Claudio
  1. Al correr git clone, la primera vez se abre una ventana “Connect to GitHub”. Elegí Sign in with your browser.
  2. En la página de GitHub que se abre en el navegador, no escribas usuario ni contraseña: hacé clic en Continue with Google.
  3. Elegí el Gmail de Claudio (claudio.ruizdiaz@gmail.com). Si Google pide un código o una confirmación en el celular, la hace Claudio.
  4. Cuando GitHub pregunte si autorizás a Git Credential Manager, aceptá (Authorize). Aparece un aviso de que la autenticación fue correcta y la descarga sigue sola.
Queda guardado en Windows: los git pull y las subidas siguientes ya no piden iniciar sesión.

Al terminar queda el proyecto en C:\Videos\video.

Abrilo en VS Code: Archivo → Abrir carpeta… → C:\Videos\video. Si pregunta si confiás en los autores de la carpeta, respondé que sí.

Lo que no viene en el repositorio
Git trae el código, los guiones, las plantillas, los datos (transcripciones, JSON) y las imágenes de personajes. No trae videos, audios, la música bajada de Mixkit, los renders ni los archivos .ai y modelos 3D de los personajes (C:\Videos\personajes): son pesados y se pasan aparte (Drive, pendrive), o los regenera Claude cuando se puede.

5Instalar y abrir Claude Code

Claude Code es el asistente que hace el trabajo: instala la suite, arma los videos, corre las herramientas y sube los cambios. Hay dos formas de usarlo; con una alcanza.

Opción A — Extensión de VS Code (la más cómoda)

  1. En VS Code, pestaña Extensiones (Ctrl+Shift+X), buscá Claude Code (de Anthropic) e instalala.
  2. Aparece el ícono de Claude en la barra lateral. Abrilo e iniciá sesión con tu cuenta de Claude.

Opción B — En la terminal

  1. En PowerShell: 
    irm https://claude.ai/install.ps1 | iex
  2. En VS Code abrí una terminal (Terminal → Nueva terminal; queda en la carpeta del proyecto) y escribí claude. La primera vez te pide iniciar sesión en el navegador.
Siempre desde la carpeta del proyecto
Claude lee al arrancar el archivo CLAUDE.md del proyecto, que tiene todas las reglas de la suite (formatos, carpetas, qué herramienta usar para cada cosa). Por eso tiene que abrirse con C:\Videos\video como carpeta de trabajo.

6Pedirle a Claude que instale todo

El proyecto trae las instrucciones completas de instalación en setup/prompt_instalacion.txt. Ese archivo ya incluye todas las herramientas: Blender, lip sync, cámara lenta, voces, modelos de inteligencia artificial y los paquetes de Python. Al lado está el inventario con las versiones probadas (setup/all_requeriments.txt). Copiá y pegá este mensaje en Claude Code:

Acabo de clonar este proyecto en una PC nueva. Instalá y dejá verificada toda la suite de producción de video: 1. Seguí paso a paso las instrucciones de setup/prompt_instalacion.txt (el inventario con versiones y fuentes está en setup/all_requeriments.txt). 2. Pedime permiso antes de instalar software del sistema (winget o instaladores). 3. Creá C:\Videos\_herramientas\equipo.json con los datos y el rendimiento de esta PC. 4. No instales ProPainter ni configures ElevenLabs: son opcionales. 5. Al final corré node scripts/verificar-suite.mjs, npm test y npm run lint, y dame un resumen corto: qué quedó instalado, cuánto mide el rendimiento de esta PC y qué falta hacer a mano.
  • Va a pedir permisos. Cuando quiera instalar algo con winget o ejecutar comandos, aceptá. Windows puede mostrar además una ventana de “¿Permitir cambios?”: también aceptá.
  • Tarda. Entre 1 y 2 horas según la conexión: solo el modelo de Whisper son ~870 MB, Blender ~400 MB, el de borrar personas ~200 MB y PyTorch varios cientos más. Podés dejarlo trabajando y mirar de vez en cuando por si pregunta algo.
  • Es reanudable. Si se corta la luz o cerrás la ventana, volvé a pegar el mismo mensaje: revisa lo que ya está hecho y sigue desde ahí.
  • Al final tiene que decir que verificar-suite, los tests y el lint dan bien. Si en la línea de Mixkit dice “N faltan”, es normal: la música no viaja por Git; copiá la carpeta public\biblioteca desde la PC de Claudio. Si algo más quedó pendiente, pedile que lo resuelva o avisale a Claudio.

7Tips para usar la suite

Hablale normal, en castellano

No hace falta saber programar. Contale qué video querés como se lo contarías a un editor: cliente, qué pieza es, formato (horizontal 16:9 o vertical 9:16 para reels/historias), duración, tono, música, textos, dónde están los crudos. Cuanto más concreto, menos idas y vueltas. Si no nombrás un trabajo, te va a preguntar si es uno nuevo o la continuación de otro.

Cómo se organiza el trabajo

Cada pedido es un trabajo con un ID del tipo 2026-10-23_cliente_pieza. El recorrido típico:

/nuevo-trabajo→/guion→editás el guion→/aplicar-guion→revisión→render final→/cerrar-trabajo
ComandoPara qué sirve
/nuevo-trabajo cliente pieza [crudos] [brief]Abre un trabajo: carpetas, ficha TRABAJO.md, proxies livianos de los crudos y registro en Remotion.
/guionEscribe el guion audiovisual con tiempos. El guion es la fuente de verdad de cada pieza. Podés anotar en una toma “motion blur” o “estela” NUEVO.
/aplicar-guion <ID>Después de que edites o pegues un guion nuevo, aplica solo lo que cambió y saca una versión nueva.
/estado (o /estado todos)Lista los trabajos abiertos (o todos), su última entrega y lo que falta.
/a-premiere <ID>Exporta la edición a Adobe Premiere (XML con cortes y audio + capa de gráficos con transparencia).
/cerrar-trabajo <ID>Verifica entregas, actualiza la ficha y archiva el material pesado.
/rig-personaje, /personaje-3dSuman un personaje animable a la biblioteca (desde su archivo .ai) y su versión 3D en Blender.

Dónde va cada cosa

CarpetaQué hay
C:\Videos\crudos\<ID>\Los originales tal cual llegaron (4K, etc.). Nunca se modifican. Copiá ahí el material antes de abrir el trabajo.
public\trabajos\<ID>\Proxies, audio preparado, imágenes y datos del trabajo.
src\trabajos\<ID>\Ficha TRABAJO.md, guiones y composiciones.
out\<ID>\revision\Cuadros sueltos y hojas de contacto para revisar.
out\<ID>\final\Entregas: pieza_9x16_v1.mp4, v2… Nunca se pisa una versión: cada cambio es una nueva.

Revisar antes de renderizar

  • Claude no hace el render completo salvo que se lo pidas: para revisar arma una hoja de revisión automática con los cuadros donde algo cambia de golpe, marcados en rojo (cortes, globos, poses), en out\<ID>\revision\. Mirá esas imágenes y pedí cambios.
  • Para ver el video en movimiento: pedile “abrí el Studio” (o en la terminal npx remotion studio) y se abre en el navegador con la línea de tiempo.
  • Cuando esté aprobado, pedí explícitamente “render final”. El audio sale normalizado a -14 LUFS (el estándar de redes) y con el desfase de Remotion corregido, así la voz queda en sincro con la boca.
  • NUEVO Antes de cada entrega, Claude pasa un detector de glitches: avisa si hay cuadros vacíos, congelados o flashes de 1 a 3 cuadros.

Reels de entrevista o persona hablando

Para estos reels hay criterios ya acordados con los clientes (color, planos, zoom, subtítulos, gráficos, audio) en src\plantillas\HablaSubtitulada\CRITERIOS_REEL.md. Claude los aplica de entrada; si un cliente corrige algo nuevo, pedile que lo sume ahí.

Trabajar en equipo con Git

  • Al empezar el día: pedile “traé lo nuevo del repo” (hace git pull), así tenés lo último que subió Claudio. Si los dos cambiaron cosas, Claude las mezcla sin perder lo tuyo: primero guarda tus cambios y después trae los del otro.
  • Al terminar algo: pedile “commiteá y subí los cambios”. Mensajes claros ayudan a saber después qué se hizo.
  • Evitá que los dos trabajen a la vez sobre el mismo trabajo o la misma plantilla; si pasa, Claude puede mezclar los cambios, pero conviene coordinar.
  • Los videos, audios y renders no viajan por Git: si Claudio necesita tus crudos o tus entregas, pasalos por Drive o pendrive.

Rendimiento

  • Todo corre en el procesador: transcribir, renderizar y Blender pueden tardar. Para cosas largas Claude las corre en segundo plano y te avisa al terminar.
  • El motion blur cuesta más o menos el doble de render, pero solo en los tramos rápidos; los borradores lo hacen con la mitad de muestras.
  • Renders muy largos se pueden repartir en partes (y hasta entre dos PC) con render_partes.mjs: pedíselo si un render se hace eterno.
  • Al cerrar un trabajo, /cerrar-trabajo saca el material pesado de public\: así los renders de los demás trabajos siguen rápidos.

8Si algo falla

  • Primero, contale a Claude qué pasó (pegá el error o una captura). Casi siempre lo resuelve.
  • Para chequear que la suite está sana: node scripts/verificar-suite.mjs --rapido (o pedile “verificá la suite”).
  • Después de un git pull con cambios grandes: pedile “fijate si hay que instalar algo nuevo”. Corre npm install y la verificación rápida, y si hace falta suma lo que esté en setup/all_requeriments.txt.
  • “ffmpeg no se reconoce” en Git Bash: es normal, Git Bash no ve los programas instalados con winget; los scripts usan la ruta fija C:\Videos\_herramientas\ffmpeg. Si Windows actualizó ffmpeg y esa ruta dejó de andar, pedile a Claude que rehaga el acceso fijo.
  • Un render falla con “no se encuentra el archivo”: faltan los videos o audios de ese trabajo en public\trabajos\<ID>\ (no viajan por Git). Pedíselos a Claudio.
  • Git pide usuario y contraseña o dice “repository not found”: el inicio de sesión no quedó hecho con la cuenta de Claudio. Repetilo con Continue with Google y el Gmail de Claudio (paso 4); si quedó guardada otra cuenta, pedile a Claude que borre la credencial de GitHub guardada en Windows.
  • Si nada de eso funciona, avisale a Claudio con el mensaje de error.
